# s43-anonymised-prior-fixtures: Anonymise prior production data into test fixtures

- Issue: #43
- Wave: 4 (owns `cashapp/tools/anonymise/`, `api/tests/fixtures/prior/`, `api/tests/test_no_identifiers.py`)
- breaking: false

## Story

As the builder of the matcher, auto-fix engine and eval, I want the previous build's production day and the AR-labelled failure set as anonymised fixtures, so that we test against real shapes without real identities.

## Context

Reference doc §6 (242 messages, 122 failed payments, 331 failed lines hand-labelled into four buckets). The source data never enters the repo; it needs Jonathan to supply it locally. Until then this story is built against a synthetic source sample in the same shape (generated by the tool's own `--synthetic` mode), and the real fixtures are produced later by running the same command.

## Acceptance criteria

1. [unit] `uv run python -m cashapp.tools.anonymise --source <dir outside repo> --out api/tests/fixtures/prior --key-file <path outside repo>` pseudonymises consistently with a keyed HMAC: customer names → `Customer-XXXX`, account numbers → `9XXXXXXX` (same length class), invoice/receipt/reference numbers → `INV-…`/`RCPT-…` preserving suffixes like `-1`, payer emails/names removed, amounts scaled by a per-customer factor and quantised to 2 dp (INR whole-rupee property preserved), dates shifted by a constant offset; the same input maps to the same output across files, so relationships survive (test).
2. [unit] Output format (pinned for s24, s12): `prior/day/messages.jsonl` (one `{message_id, extraction: RemittanceExtraction-shaped JSON, outcome: {payment_status, lines:[{transaction_number, line_status, applied_amount}]}}` per line), `prior/day/fusion.json` (FusionScenario-shaped transactions/receipts/relationships), `prior/labelled/failures.jsonl` (`{message_id, label: "receipt_in_fusion"|"not_yet_entered"|"not_in_fusion"|"future", fusion_amount, line_labels:[...]}`).
3. [unit] AR's four labels are kept as expected outcomes, and each label maps to the expected auto-fix decision (`receipt_in_fusion` → matched; `not_yet_entered` / `future` → AWAITING_RECEIPT; `not_in_fusion` → escalation after aging).
4. [unit] `cashapp/tools/anonymise/scan.py`: `scan_for_identifiers(text, denylist) -> list[Finding]`; `api/tests/test_no_identifiers.py` scans every file under `api/tests/fixtures/`, `docs/` and `api/src/` for (a) any term in a denylist loaded from a file path in env `CASHAPP_IDENTIFIER_DENYLIST` (kept outside the repo; test skipped with a warning when unset) and (b) structural patterns (emails, IBAN-like and long account-like numbers not prefixed by an anonymised marker).
5. [unit] `--synthetic` generates a source sample of the same shape (fake names) so tests and s24 run before real data arrives; the committed fixtures are clearly marked `synthetic: true` in `prior/README.md` until replaced.

## Out of scope

Evaluations (s24); the source data itself.
