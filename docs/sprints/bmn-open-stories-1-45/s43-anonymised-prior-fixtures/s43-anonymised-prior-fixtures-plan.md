# s43-anonymised-prior-fixtures: plan

Issue #43, wave 4, breaking: false. No LLM, no UI, no DB, no Fusion calls. A local, offline CLI that
turns the previous build's production day (and AR's labelled failure set) into anonymised fixtures,
a synthetic source generator so everything runs before the real data exists, and an identifier
scanner plus a repo-wide scan test.

## Standards followed

- **CLAUDE.md**: no client or customer names in code, tests, fixtures or docs (the scan test is the
  enforcement); customer PII stays local (the source folder and HMAC key must be outside the repo,
  refused otherwise); money is `Decimal`, 2 dp, `ROUND_HALF_UP` via s02 `to_money` / `money_eq`; one
  status enum (outcomes use s02 `PaymentStatus` / `LineStatus`, never new strings); one error-code
  enum (label expectations use s02 `ErrorCode` / `ItemState`); DRY (fusion.json is produced in the
  pinned s05 `FusionScenario` JSON shape, extractions are built with s08's `RemittanceExtraction`
  model, not a copy).
- **python-web-app:building-python-web-apps**: `src/` layout under `cashapp`, typed modules, pytest;
  the CLI uses `typer` (already pinned by s01; no lockfile change).
- **python-library-quality:guarding-destructive-operations** (applied by reference): guards run before
  the first read/write; path containment is checked on resolved paths (`Path.resolve()` +
  `is_relative_to`), never by string prefix; the output folder is never `rmtree`d, only the five
  managed files are replaced, from a temp folder, after the output passed the scan.
- **Layering**: this is a tool under `cashapp/tools/`; it imports only `cashapp.domain.*` (s02, s08).
  It never imports `tests.*` (src must not depend on tests); round-trip with s05's
  `load_scenario` is proved in tests.
- **pyright strict on `src`**: every module fully typed; Pydantic v2 models for source and output rows.
- **Logging/printing**: the CLI prints counts only (messages, lines, customers, clusters, findings).
  It never prints a source value, a pseudonym mapping or the key. Scanner findings print a masked
  excerpt only (first char + `***` + length), so CI output never leaks a denylisted term.

## Design

### CLI (AC1, AC5)

```
uv run python -m cashapp.tools.anonymise --source <dir> --out api/tests/fixtures/prior --key-file <path>
                                         [--denylist <path>] [--init-key]
uv run python -m cashapp.tools.anonymise --synthetic [--seed 43] [--messages 40] --out <dir>
                                         [--source-out <dir>]
```

- Exactly one of `--source` / `--synthetic` (else exit 2). `--key-file` is required with `--source`
  and refused with `--synthetic`.
- Guards, all before any read: `--source` and `--key-file` must resolve outside the git work tree
  (`find_repo_root` walks up for a `.git` dir **or file**, so worktrees work) → `PathGuardError`,
  exit 3. `--out` must not resolve inside `--source`. `--denylist` (default: env
  `CASHAPP_IDENTIFIER_DENYLIST`) must also be outside the repo.
- `--init-key`: creates the key file with `secrets.token_bytes(32)` only when absent (never
  overwrites), mode 0600 where supported. `load_key` refuses files < 32 bytes (`KeyFileError`, exit 3).
- `--synthetic`: writes the synthetic source to `--source-out` (default: a `tempfile` dir outside the
  repo, deleted afterwards), then runs the same `load_source` → `anonymise` → `write_fixtures` path
  with `synthetic_key(seed)` = `sha256(b"cashapp-synthetic-fixture-key\x00" + str(seed))`. This key is
  deliberately public: the data it protects is fake, and it makes committed fixtures reproducible.
- Exit 0 prints one summary line of counts. Exit 4 = output scan found identifiers (nothing written
  to `--out`; temp folder removed; masked findings printed). Exit 5 = `SourceFormatError` (message
  names the file, line and field, never the value).

### Source format (the real export is adapted to this in `source.py` only)

Folder layout read by `load_source(dir) -> SourceBundle` (UTF-8; CSV via `csv.DictReader`):

- `messages.jsonl`: `{message_id, payload, outcome}` where `payload` is the prior extraction contract
  (reference §2: `payerName`, `payments[]{reference_number, payment_amount, payment_date,
  payment_currency, allocations[]{application_type, invoice_number, applied_amount,
  credit_memo_id}}`, `paymentSummary`, `status`, `statusDescription`) and `outcome` is
  `{payment_status, lines[{invoice_number, line_status, applied_amount}], receipt_number|null}`.
  `invoice_number` / `reference_number` are read as **strings**; a JSON number is converted with
  `format(Decimal(str(v)), "f")` and counted in the summary as `numeric_ids_coerced` (the old
  `2.598014E6` defect; exponent forms are a `SourceFormatError`, never silently expanded).
  Multiple `payments[]` in one message → one output row per payment, `message_id` suffixed `#n`
  (n ≥ 2) before pseudonymising.
- `fusion/customers.csv` (`account_number,name,currency_codes`; `;`-separated),
  `fusion/transactions.csv` (`number,kind,original_amount,balance,currency,status,
  bill_to_customer_number,bill_to_site,business_unit,payment_terms`),
  `fusion/receipts.csv` (`receipt_number,amount,unapplied_amount,currency,customer_account_number,
  receipt_date,creation_date,status,state,remittance_references,comments,payer_bank_account`),
  `fusion/applications.csv` (`receipt_number,transaction_number,amount_applied,apply_date`),
  `fusion/relationships.csv` (`account_number,related_account_number`).
- `labelled/failures.csv`: `message_id,payment_label,payment_fusion_amount,transaction_number,
  line_label,line_fusion_amount` (one row per failed line; payment columns repeated). Labels pass
  through `LABEL_ALIASES` (case-insensitive human phrasings → `PriorLabel`); unknown → error.
- Old status strings map through `STATUS_ALIASES` onto s02 enums; the only non-identity entry pinned
  now is `"payment-apply-failed" → PaymentStatus.PAYMENT_APPLY_FAILED_SYSTEM` (s02 split it).
  Unknown status → `SourceFormatError`.

### Pseudonymisation (AC1) — `Pseudonymiser(key: bytes)`

`digest(kind, value) = HMAC-SHA256(key, kind + "\x00" + normalise(value))`; `normalise` = NFKC,
strip, collapse whitespace, casefold (names) / strip only (numbers). Vocabulary is assigned in two
passes (`register(kind, value)` for every value in the bundle, then `freeze()`), sorted by digest,
so output does not depend on file or row order. Collision between two distinct inputs of one kind →
both get a longer code (4→6→8 chars, digits 8→10→12); never an error, never order-dependent.

| Kind | Output |
|---|---|
| customer name | `Customer-` + 4 uppercase base32 chars (`Customer-K7QD`) |
| account number (customer, bill-to, related, receipt owner) | `9` + digits, length class: ≤6 → 6, 7–9 → 8 (`9XXXXXXX`), ≥10 → 10 |
| invoice / credit-memo number | `INV-` + 8 digits + preserved suffix; suffix = `-\d{1,2}$` split first, so `X` and `X-1` share the base |
| receipt number | `RCPT-` + 8 digits + preserved suffix |
| remittance / reference number | `REF-` + 8 digits |
| PO / sales order / ERS | `PO-` / `SO-` / `ERS-` + 8 digits |
| message id | `MSG-` + 8 digits (`#n` → `-Pn`) |
| payer bank account | `BANK-` + 8 digits (kept as an equality signal for s12; s12 hashes it again) |
| business unit / bill-to site | `BU-` + 2 chars / `SITE-` + 4 chars |
| payment terms | kept only if it matches `GENERIC_TERMS` (`IMMEDIATE`, `NET n`, `n% n NET n`, case-insensitive), else `TERMS-` + 2 chars |
| payer name, emails | **removed**: `payer_name.value=None`; emails in any text → `[email]` |
| free text (receipt comments) | `scrub_text`: every registered source value (longest first) replaced by its pseudonym, emails → `[email]`, remaining digit runs ≥ 6 → `[number]` |
| `paymentSummary`, `statusDescription`, notes | dropped |
| dates / datetimes | shifted by one constant offset `-7 * (35 + int(digest("date-offset", "")) % 52)` days (whole weeks, so weekdays and business-day logic survive); times and offsets kept |
| Fusion internal ids | re-sequenced in pseudonym order: transactions 100001…, receipts 500001…, applications 900001… (s05 convention) |

### Amounts (AC1) — `AmountMapper`

- **Clusters, not single customers**: `ClusterIndex` unions accounts linked by relationships, by a
  message's lines' bill-to customers, by a message's outcome receipt owner, and by applications.
  A message with no resolvable account forms its own cluster keyed by its message id. Every amount
  belongs to exactly one cluster. (Deviation from "per-customer factor": a pay-on-behalf receipt and
  the invoices it pays must share a factor or equality is lost. Logged under Assumptions.)
- Factor per cluster: `f = Decimal(70 + h % 61) / 100` with `h = int(digest("factor", cluster_key))`,
  re-drawn (next digest) while `0.97 ≤ f ≤ 1.03`. `cluster_key` = smallest pseudonymised account in
  the cluster (order-independent).
- `map(x, cluster, currency)`:
  1. `0` → `0`; sign preserved (credit memo balances stay negative); work on `|x|`.
  2. **Memo**: the same `|x|` in the same cluster always maps to the same output (so line = balance,
     receipt = payment header, `unapplied = amount` stay equal).
  3. **Sums first**: before singles, for each payment whose header `money_eq` the sum of its lines,
     the header is mapped as the sum of the mapped lines and memoised.
  4. **Small residuals**: if a memoised `|y|` exists in the cluster with `0 < ||x| − |y|| ≤ 5.00`
     (`RESIDUAL_BAND`), output `memo[y] + (|x| − |y|)` exactly (nearest `y`, ties → smaller `y`),
     so bank-fee/short-pay/tolerance residuals (±0.10, ±0.49) keep their absolute size.
  5. Otherwise `to_money(|x| * f)` (`ROUND_HALF_UP`, 2 dp).
  6. **INR whole-rupee**: for `currency == "INR"`, a whole-rupee input maps to a whole-rupee output
     (step 5 quantises to 0 dp `ROUND_HALF_UP`), and a non-whole input never lands on a whole rupee
     (+0.01 if it would). Residual rule 4 keeps paise differences.
  7. Processing order (pinned, deterministic): per cluster, sums → payment headers → lines →
     transactions (original, balance) → receipts (amount, unapplied) → applications → label
     `fusion_amount`s, each group sorted by pseudonym.
- Fusion consistency after mapping: `balance` for an invoice with applications is recomputed as
  `original − Σ applications` only when that held in the source (`money_eq`); otherwise mapped.

### Output format (AC2, pinned for s24 and s12) — `fixture_format.py`

`FORMAT_VERSION: Final = "1"`. All JSON UTF-8, LF line endings, `sort_keys=True`, money as strings
(2 dp), dates ISO 8601. Rows sorted by `message_id`.

```python
class PriorLabel(StrEnum):
    RECEIPT_IN_FUSION = "receipt_in_fusion"; NOT_YET_ENTERED = "not_yet_entered"
    NOT_IN_FUSION = "not_in_fusion"; FUTURE = "future"

class OutcomeLine(BaseModel, frozen=True):
    transaction_number: str; line_status: LineStatus; applied_amount: MoneyStr | None
class PriorOutcome(BaseModel, frozen=True):
    payment_status: PaymentStatus; lines: list[OutcomeLine]; receipt_number: str | None = None
class PriorMessage(BaseModel, frozen=True):            # one line of prior/day/messages.jsonl
    message_id: str; extraction: RemittanceExtraction; outcome: PriorOutcome
class LineLabel(BaseModel, frozen=True):
    transaction_number: str; label: PriorLabel; fusion_amount: MoneyStr | None
class PriorFailure(BaseModel, frozen=True):            # one line of prior/labelled/failures.jsonl
    message_id: str; label: PriorLabel; fusion_amount: MoneyStr | None; line_labels: list[LineLabel]
class PriorManifest(BaseModel, frozen=True):           # prior/manifest.json
    format_version: str; synthetic: bool; seed: int | None; key_id: str; generated_by: str
    counts: dict[str, int]
class PriorFixtures(BaseModel, frozen=True):
    messages: list[PriorMessage]; fusion: dict[str, Any]; failures: list[PriorFailure]; manifest: PriorManifest

def load_prior_day(prior_dir: Path) -> tuple[list[PriorMessage], dict[str, Any]]   # (messages, fusion.json dict)
def load_labelled(prior_dir: Path) -> list[PriorFailure]
def load_manifest(prior_dir: Path) -> PriorManifest
DEFAULT_PRIOR_DIR: Final[str] = "tests/fixtures/prior"      # relative to api/
```

`extraction` mapping from the prior contract: `payer_name` = `Extracted(value=None, confidence=0.0)`;
`payer_bank_account` = `BANK-…` or None; `remittance_reference` = `REF-…`; `payment_amount`,
`currency_raw` (the source currency string), `currency` (the code when it is a valid ISO code, else
None with `currency_ambiguous` per s08's validator), `payment_date` and one `DateCandidate(kind=PAYMENT)`;
lines: `application_type` `"Payment"` → `LineKind.INVOICE`, `"Credit Memo"` → `CREDIT_MEMO`,
`amount_paid` = mapped `applied_amount` or None (no-amount lines kept); `po_refs`/`sales_order_refs`/
`ers_refs` empty unless present in the source. Present values carry `confidence=1.0` and
`source=SourceLocation(part_no=1)`; absent values `value=None, confidence=0.0`. Built through s08's
`RemittanceExtraction.model_validate` and dumped with `model_dump(mode="json")`, so the row is the real
schema (s08's `SCHEMA_VERSION` recorded in the manifest as `extraction_schema_version`).

`fusion.json` = s05's pinned `FusionScenario` JSON shape exactly (`customers`, `transactions`,
`receipts`, `applications`, `relationships`, `reports: {}`), so `FakeFusionClient.from_json` /
`load_scenario` read it unchanged.

### Synthetic source (AC5) — `synthetic.py`

`write_synthetic_source(dir: Path, *, seed: int = 43, messages: int = 40) -> None` (`random.Random(seed)`,
no wall clock). Names are obviously fake (`Synthetic Payer 001`, `synth-007@example.com`), account
numbers 4–9 digits, all within a fixed 2026-03 week. Guaranteed coverage regardless of `messages`
(minimum 12): credit memo suffix `-1`/`-2` sharing a base with an invoice; a numeric
`invoice_number` in JSON; a no-amount line; header ≠ sum of lines; INR whole-rupee receipt vs paise
invoices; a ±0.07 bank-fee residual; a short pay; a pay-on-behalf relationship (receipt owned by the
related account); a message with no resolvable customer; a duplicate invoice in one remittance;
`receipt-not-found`, success, apply-failed and customer-not-found outcomes; all four labels, with
`not_yet_entered`/`future` receipts absent from `receipts.csv` and `receipt_in_fusion` receipts
present; a receipt comment containing a payer name and an email (proves `scrub_text`).

### Writer and scan gate — `writer.py`

`write_fixtures(fixtures, out: Path, *, denylist: Sequence[str], synthetic: bool) -> WriteResult`
writes `README.md`, `manifest.json`, `day/messages.jsonl`, `day/fusion.json`, `labelled/failures.jsonl`
into `out.parent / f".{out.name}.tmp-{uuid}"`, runs `scan_paths` (structural + denylist) over them,
and only on zero findings replaces those five files in `out` (`os.replace` per file; other files in
`out` untouched). Findings → raises `IdentifierFoundError(findings)`; temp dir removed either way.
README first line is exactly `synthetic: true` or `synthetic: false`, then provenance (format
version, seed or "real source", key id, command to regenerate, "never commit the key or source").

### Scanner (AC4) — `scan.py`

```python
class FindingKind(StrEnum): DENYLIST = "denylist"; EMAIL = "email"; IBAN = "iban"; ACCOUNT_NUMBER = "account_number"

@dataclass(frozen=True)
class Finding:
    kind: FindingKind
    line: int                  # 1-based
    column: int                # 1-based
    length: int
    masked: str                # first char + "***" + f"({length})"; never the full match
    path: str | None = None    # repo-relative, set by scan_paths

def scan_for_identifiers(text: str, denylist: Sequence[str] = ()) -> list[Finding]
def load_denylist(path: Path) -> tuple[str, ...]      # one term per line, '#' comments, blanks skipped; terms < 3 chars dropped
def iter_scannable_files(roots: Sequence[Path]) -> Iterator[Path]   # skips __pycache__, .pyc, binaries (NUL in first 8 KiB), files > 5 MiB
def scan_paths(roots: Sequence[Path], denylist: Sequence[str] = (), *, base: Path) -> list[Finding]
ANONYMISED_MARKERS: Final[tuple[str, ...]] = ("Customer-", "INV-", "RCPT-", "REF-", "PO-", "SO-", "ERS-", "MSG-", "BANK-", "BU-", "SITE-", "TERMS-")
```

- Denylist: case-insensitive (casefold), whitespace-collapsed, matched on word boundaries where the
  term's edge is alphanumeric.
- Email: standard address regex; allowed only for reserved domains (`example.com/.org/.net`,
  `*.example`, `*.test`, `*.invalid`, `*.localhost`) and the commit-attribution
  `noreply@anthropic.com`.
- IBAN-like: `\b[A-Z]{2}\d{2}(?:[A-Z0-9]{11,30}|(?: ?[A-Z0-9]{4}){3,7}(?: ?[A-Z0-9]{1,3})?)\b`.
- Account-like: a digit run of ≥ 8 digits `(?<![\w.,-])\d{8,}(?![\w.,])` (so amounts, decimals,
  `AR-855287`, hex hashes and marker-prefixed codes like `INV-12345678` don't match), except an
  anonymised account (`^9\d{5}$|^9\d{7}$|^9\d{9}$`) — the denylist is the guard for real values that
  happen to start with 9 (noted in Risks).

## Risks

- **Real export shape is unknown.** Pinned source format is an assumption; adapting the real export
  touches only `source.py` (and maybe `STATUS_ALIASES` / `LABEL_ALIASES`). Output format stays pinned.
- **False positives in the repo scan** (docs or src containing ≥ 8-digit runs or IBAN-shaped strings):
  the coder runs the scan once over the tree during step 4 coding and narrows the regex only within
  this plan's rules; no per-file allowlist. Other wave-4 stories adding docs can turn this test red —
  that is intended.
- **Account-like exemption** (`9` + 5/7/9 digits) would let a real 9-prefixed account through the
  structural scan; the denylist (real account numbers listed by Jonathan) is the guard for real data.
- **Amount relationships beyond those pinned** (e.g. a residual > 5.00 that mattered) are scaled, not
  preserved; s24 agreement on such cases may drift. The residual band is one constant.
- **`api/.env` with `CASHAPP_IDENTIFIER_DENYLIST`**: s27 `Settings` uses `extra="forbid"` with prefix
  `CASHAPP_`; a dotenv entry could fail settings boot. README says set it in the shell, not `.env`.
- **s08/s05 shapes evolve**: fixture tests validate against the live models, so drift shows as a red
  test and a regeneration with `--synthetic`, not silent corruption.
- **CRLF on Windows**: files written with `newline="\n"`; reproducibility test compares parsed content.

## Assumptions / deviations

- Amount factor is per **relationship cluster** (customers linked by pay-on-behalf, shared
  remittances or applications), not per single customer, so cross-customer equalities survive.
- Payer bank account is pseudonymised (`BANK-…`) rather than removed (AC removes names and emails
  only); it keeps s12's bank-account signal measurable without exposing a value.
- Business unit, site and non-generic payment-term names are pseudonymised (they can identify the
  client); not listed in the AC.
- The prior contract has no per-field confidence; present values get `1.0`, absent `0.0`.
- Old `payment-apply-failed` maps to `PAYMENT_APPLY_FAILED_SYSTEM` (s02 split the status).
- `not_in_fusion` first parks (`RECEIPT_NOT_YET_AVAILABLE` → AWAITING_RECEIPT) and reaches ESCALATED via
  `AGED_OUT` (s14 aging), matching "escalation after aging".
- The synthetic key is derived from the seed and is public by design; real runs require a key file
  outside the repo.
